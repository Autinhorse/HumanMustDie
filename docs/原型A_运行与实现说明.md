# 原型 A：灰盒杀戮走廊 — 运行与实现说明

对应设计文档 v0.1 的 §17 里程碑 A 与 §21 首轮实现任务。
引擎 Godot 4.7 + GDScript，数值全部外置在 `data/*.json`。

---

## 1. 怎么跑

| 目的 | 命令 |
| --- | --- |
| 编辑器打开 | 用 Godot 4.7 打开 `project.godot` |
| 直接运行 | `C:\Godot4.7\Godot_v4.7-stable_win64.exe --path .` |
| 跑自动化测试 | `C:\Godot4.7\Godot_v4.7-stable_win64_console.exe --headless --path . res://tests/run_tests.tscn` |
| 看连锁演示（自动搭杀戮区并开打） | `C:\Godot4.7\Godot_v4.7-stable_win64.exe --path . res://tests/demo.tscn` |

测试全部通过时退出码为 0，失败为 1，可直接接 CI。

## 2. 操作

| 输入 | 作用 |
| --- | --- |
| `1`–`5` / 点工具条 | 选择要放置的机关 |
| 左键 | 放置机关；没选机关时＝选中敌人或已放置的机关查看信息 |
| 按住 `Shift` 放置 | 连续放置同一种机关 |
| `R` | 旋转朝向（地面方向机关四向；墙面机关在该墙的可用面之间循环） |
| 右键 / `Esc` | 取消放置 / 取消选中 |
| `X` | 拆除选中的机关（返还 60%） |
| `Enter` | 开始下一波 |
| `空格` | 暂停 / 继续 |
| `Tab` | 战斗统计面板 |
| `WASD` / `Q`·`E` / 滚轮 | 平移 / 转视角 / 缩放 |
| `F1` | 沙盒模式：无限金币、战斗中也能施工、`Z`/`C`/`V` 手动放 小兵/狂战士/巨魔 |
| `F2` | 重开 |
| `F5` | 重载 `data/` 下的配置并重开本局（改数值不用重启） |

放置时会实时显示覆盖格与朝向箭头，不合法的位置显示红色并给出原因（文档 §14.2）。

## 3. 已实现范围

按 §21 的口径，本轮只做灰盒垂直切片：

- **固定走廊地图**：`data/levels/corridor_01.json`，14×20 格，一个入口、一个 2×2 核心、中段一条 2 格宽的窄桥横跨镂空区。
- **格子类型**完全按 §5.3：`0 空地 / 1 普通地面 / 2 墙 / 3 障碍 / 4 桥面 / 5 核心`。
- **入口推导**按确认的规则：地图边缘上离核心最远的那个连通开口（地面或桥面）整段作为出生点，敌人成堆涌入。
- **墙面放置规则**按确认的规则：墙格的四个侧面中，只有正对另一面墙的那一面不可用，其余暴露面（含朝向障碍、朝向空地的面）都能放机关。
- **5 种机关**：地刺、黏胶地面、弹射板、推墙、旋转锯墙。
- **3 类敌人**：小兵（小型）、狂战士（中型）、巨魔（重型）。
- **物理**：质量 / 稳定值 / 冲击积累三属性，击飞、滑行、撞墙反弹、落地伤害、坠落处决、被击飞单位撞伤沿途敌人。
- **5 波手工波次**、金币、核心生命、胜负与重开流程。
- **可复现性**：固定步长（1/60）+ 固定种子，战斗日志可导出到 `%APPDATA%\Godot\app_userdata\...\logs\`。
- **统计面板**：分机关的伤害 / 击杀 / 控制秒 / 位移次数 / 连锁击杀，坠落击杀占比，进坑次数，每波准备与战斗用时（文档 §18）。

明确没做（§21 要求排除）：地块抽取与旋转、工程改造、元素系统、自动英雄、局外成长、正式美术。

## 4. 数据配置

改这四个文件就能改玩法，不用碰代码；游戏内 `F5` 热重载。

### `data/config.json`
| 段 | 说明 |
| --- | --- |
| `grid` | 格子边长、墙高、地板厚度与地下支撑长度、格缝 |
| `camera` | 俯角、朝向、距离与缩放范围、平移速度 |
| `sim` | 固定步长、每帧最大步数、可选倍速、**随机种子** |
| `combat` | 重力、地面摩擦、冲击→速度换算、坠落判定高度、撞击伤害系数与阈值、落地伤害、连锁判定窗口、拥挤分离强度 |
| `economy` | 初始金币、核心生命、清波奖励、拆除返还比例 |
| `entrance` | 入口推导规则 |
| `debug` | 沙盒金币、是否打击杀日志 |

### `data/enemies.json`
`hp` / `speed` / `mass` / `stability`（位移阈值）/ `impact_decay`（每秒冲击衰减）/ `gold` / `core_damage` / `radius` / `height` / `color`。

三档的设计意图：小型 `stability = 0`，任何冲击都直接击飞；中型 18，需要两次推墙或推墙＋弹射板；重型 45，需要五次推墙，且位移速度 = 冲击 ÷ 质量，所以只会短距离滑一段，但滑动过程中会撞伤旁边的小怪。

### `data/traps.json`
每个机关按 §15.3 拆成五段组件，加新机关基本只写 JSON：

```json
"push_wall": {
  "mount": "wall",                       // ground = 地面机关，wall = 墙面机关
  "cost": 100,
  "directional": true,
  "targeting":    { "type": "front_box", "length": 2, "width": 3 },
  "trigger":      { "type": "threshold_count", "min_count": 2, "max_wait": 2.0, "cooldown": 3.0 },
  "payload":      { "damage": 6 },       // 也支持 "dps"（持续触发按 dt 结算）
  "displacement": { "force": 9.0, "up": 0.18 },
  "status":       {}                     // 支持 { "slow": 0.45, "duration": 1.0 }
}
```

现有组件类型：
- `targeting`：`self_cell`、`front_box(length,width)`、`radius(r)`
- `trigger`：`periodic(cooldown,require_enemy)`、`continuous`、`on_enter(cooldown)`、`threshold_count(min_count,max_wait,cooldown)`

加一种新触发/新作用器＝在 `scripts/traps/` 对应文件里加一个 `match` 分支，其余四段不用动。

### `data/levels/corridor_01.json`
`grid` 是逐行的格子类型字符串，`allowed_traps` 控制工具条，`waves[].groups[]` 是 `{enemy, count, interval, delay}`。

## 5. 代码结构

```
scripts/
  config_loader.gd     Autoload「Cfg」：读 data/*.json，支持 user://data/ 覆盖
  grid.gd              逻辑网格：格子类型、坐标换算、墙面暴露判定
  flow_field.gd        核心反向 BFS 距离场：敌人寻路 + 入口推导
  game.gd              模拟核心：固定步长、波次、经济、放置校验、撞击结算、统计
  enemy.gd             敌人状态机 GROUND / THROWN(含滑行) / FALLING / DEAD
  trap.gd              机关实例，按五段组件执行
  traps/{trigger,targeting,payload,displacement,status}.gd
  stats.gd             战斗数据记录与导出
  view/board_view.gd   灰盒地图占位方块
  view/preview.gd      覆盖范围与朝向预览
  ui/hud.gd            界面
  main.gd              相机、输入、放置流程
tests/
  test_runner.gd       无头自动化测试（T0–T5）
  demo.gd              自动搭杀戮区的演示场景
```

逻辑与表现分离：`grid/flow_field/game/enemy/trap` 完全不依赖任何视觉节点，位移由游戏逻辑驱动而非刚体，因此同种子同操作可复现（§15.3）。

## 6. 验证结果

`--headless res://tests/run_tests.tscn`，六项全部通过：

| 用例 | 覆盖的问题 |
| --- | --- |
| T0 关卡与入口推导 | 网格尺寸、核心格、入口落在最远边缘开口；墙块外侧面可放机关、被墙挡住的面不可放 |
| T1 小怪被弹射板击飞并坠落处决 | §21 验证点一：小型可被直接击飞并坠落处决，坠落击杀有统计 |
| T2 中型需累计冲击 | §21 验证点二：单次推墙（9）和单次弹射板（15）都推不动稳定值 18 的中型，两次推墙才位移，位移后冲击槽清零 |
| T3 重型只短移且撞伤小怪 | §21 验证点三：巨魔需要 5 次以上推墙才动，位移速度和距离都明显更短，滑行途中撞伤旁边的小兵并计入撞击统计 |
| T4 完整一波跑通 | 放置合法性（墙格/空地/被挡住的面都被拒绝）、整波无崩溃、每只敌人都有归宿、推墙至少把一只推下桥 |
| T5 场景启动与鼠标拾取 | 主场景能起、屏幕坐标→格子拾取正确（含墙顶优先）、墙面朝向选择正确、界面回调齐全 |

演示场景实测（种子 20260911，第 1 波 8 只小兵）：**7 杀 1 漏，其中坠落处决 4（57%）、撞击击杀 1**，日志可读出完整链路「黏胶减速 → 地刺消耗 → 推墙推下桥 → 坠落处决（连锁）」。

## 7. 已知问题 / 下一步

1. **坠落击杀占比偏高**（示例 57%），正好压在文档 §19 风险二的警戒线上。深坑容量、堵塞、重型豁免都还没实现，建议下一步先加"坑有吞吐上限"再谈平衡。
2. **撞击击杀归属**记在"最后一次给它冲击的机关"名下，所以推墙的击杀数里含撞击连带。这是有意为之（用来评估连锁贡献），但读统计时要知道口径。
3. **击飞撞墙只做速度反射**，没有贴墙滑动；高速斜飞擦到墙角时轨迹会略显生硬。
4. 敌人拥挤用的是逐对分离，密集时有轻微抖动；碰撞检测是 O(n²)，当前波次量级（<60）无压力，上到几百只要换网格分桶。
5. **桥面（类型 4）目前只是"底下没有支撑的地面"**，还没有能打掉它的机关；障碍（类型 3）在本关地图里没用上。
6. 沙盒模式拆除机关不返还金币（避免刷钱），正常模式返还 60%。
7. 界面每帧重建文本，效率不高但对原型无影响。
8. 地块系统（里程碑 B）开工前还需要确认：地块之间的接口对齐规则（是否要求接口宽度一致）、三选一候选位置的挑选策略、以及旋转后不可连接时的标红判定细节。
